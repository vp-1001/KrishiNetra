# AgroDetect

AgroDetect is a crop disease image-classification project built around the
PlantVillage dataset. The work completed so far establishes the data pipeline
needed for future model training and evaluation.

## Work completed

### Dataset preprocessing

`preprocess_dataset.py` implements the dataset preparation workflow:

- Validates that the input contains all 38 expected plant-health classes.
- Supports both a class-folder dataset root and a PlantVillage directory
  containing a `train` subdirectory.
- Detects and skips corrupted images while reporting warnings.
- Creates reproducible stratified train, validation, and test splits using a
  70/15/15 ratio.
- Resizes images to `224x224`, converts them to RGB, and stores them as
  optimized JPEG files.
- Generates the class-to-index mapping and project configuration.

### PyTorch data loading

`dataset_loader.py` provides `get_dataloaders`, which creates train,
validation, and test `DataLoader` instances from the prepared directory
structure.

Training images receive random horizontal flips, rotations, and color jitter.
Validation and test images use deterministic resizing. All splits are
converted to tensors and normalized with ImageNet mean and standard deviation
values.

### Dataset metadata

- `config.py` stores the 38 class names, image size, batch size, and dataset
  paths.
- `class_indices.json` stores the numeric label assigned to each class.
- The generated dataset is organized into `train`, `val`, and `test`
  directories with one subdirectory per class.

## Current project status

The repository currently contains the dataset preparation and loading stages
of the project. Model architecture, training, evaluation, and inference
components are provided in `vgg16_training.ipynb`. The notebook trains a
two-phase VGG16 model locally and writes checkpoints, weights, metrics, and
plots to the `vgg16` directory.

# AgroDetect — EfficientNet-B0 Plant Disease Classification

AgroDetect uses the existing trained EfficientNet-B0 checkpoint for 38-class PlantVillage leaf classification, Grad-CAM explainability, and a Flask web interface. The application does not train a model at runtime.

## Project structure

```text
AgroDetect-main/
├── app.py
├── evaluate.py
├── class_indices.json
├── models/
│   └── efficientnet_b0_best.pth
├── dataset/
│   └── test/                 # 38 class folders
├── static/
│   ├── uploads/
│   └── heatmaps/
└── results/
    └── efficientnet_b0/      # generated by evaluate.py
```

Keep your existing `dataset/`, `class_indices.json`, and trained checkpoint. Place the updated `app.py` and `evaluate.py` in the project root.

## Environment

Use the same Python environment in which the current Flask app already runs. Required packages:

```powershell
pip install flask pillow numpy scikit-learn matplotlib torchvision torch
```

For NVIDIA GPU acceleration, retain the CUDA-enabled PyTorch installation already working on your machine. Do not replace it with a CPU-only build.

## Run the application

From the project root with `.venv` activated:

```powershell
python app.py
```

Open `http://127.0.0.1:5000`. The checkpoint is expected at `models/efficientnet_b0_best.pth`. An alternate checkpoint path can be supplied with `AGRODETECT_MODEL_PATH`.

## Phase 5 — Quantitative evaluation

Run:

```powershell
python evaluate.py
```

Optional batch size:

```powershell
python evaluate.py --batch-size 16 --workers 0
```

The script evaluates the existing checkpoint against `dataset/test` using the same 224×224 resize and ImageNet normalization used by the Flask app. It performs inference only and does not update model weights.

**Label-order safety:** `evaluate.py` checks that the sorted `dataset/test` class folders match `class_indices.json`. If they do not match exactly, evaluation stops rather than reporting potentially misleading metrics. Resolve the mapping against the mapping used during training before proceeding.

Generated files in `results/efficientnet_b0/`:

- `metrics.json` — accuracy, macro and weighted precision/recall/F1, sample count, device, and mapping verification.
- `classification_report.txt` and `.json` — per-class and aggregate metrics.
- `per_class_metrics.csv` — spreadsheet-friendly per-class metrics.
- `confusion_matrix.png` — raw class counts.
- `confusion_matrix_normalized.png` — row-normalized class rates.

The metrics are generated from the local test set at execution time. No metric values are prefilled in this repository.

## Interpretation and limitations

The model predicts an image-level class; its Grad-CAM overlay is an explanatory visualization, not a pixel-level lesion segmentation. It can miss infected areas or highlight unrelated features. Reliable lesion coverage requires a segmentation model trained and validated on images with pixel-level lesion masks. Predictions can be affected by image quality, lighting, cultivar, field conditions, and differences between PlantVillage images and real-world photographs. Disease-management text is general information; confirm treatment decisions with a qualified local agricultural expert.

## Model scope

This project release intentionally uses **EfficientNet-B0 only**. The checkpoint is loaded strictly; missing or unexpected parameters cause loading to fail instead of silently using random weights.
